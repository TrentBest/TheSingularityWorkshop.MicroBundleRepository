# Azure Blob Storage Setup\n\nThis repository uses Azure Blob Storage as the first durable MicroBundle artifact store.\n\n## Local proof\n\nThe first important proof is deliberately not a GitHub Actions integration test. The repository must authenticate to the real development account using the same Microsoft Entra identity used locally, while normal CI remains credential-free.\n\nAfter signing in with Azure CLI:\n\n~~~powershell\naz login\naz account show\n$env:MICROBUNDLE_STORAGE_ACCOUNT_URI = "https://<storage-account-name>.blob.core.windows.net"\ndotnet test TheSingularityWorkshop.MicroBundleRepository.slnx --configuration Release --filter FullyQualifiedName~AzureBlob_RoundTrip\n~~~\n\nThe live test is opt-in: without `MICROBUNDLE_STORAGE_ACCOUNT_URI`, it returns without touching Azure.\n\nThe round trip proves:\n\n1. `DefaultAzureCredential` can authenticate.\n2. the repository can initialize the private container.\n3. an artifact can be written to its deterministic content-addressed blob.\n4. the artifact can be retrieved using only its complete address.\n5. the retrieved bytes and address survive the trip unchanged.\n6. the repository's SHA-256 verification remains the final authority over artifact integrity.\n\nAfter the test, inspect `microbundles/artifacts/...` in the Azure portal. The blob is deliberately opaque to the application: the repository owns the mapping between artifact identity and physical blob location.\n\n## Target configuration\n\n- StorageV2\n- Standard performance\n- LRS redundancy\n- Hot access tier\n- one private `microbundles` container\n- public blob access disabled\n- secure transfer enabled\n- TLS 1.2 minimum\n- hierarchical namespace disabled\n- SFTP disabled\n- NFS disabled\n\nNo database, CDN, Front Door, geo-replication, or public artifact endpoint is required for the first vertical slice.\n\n## Portal setup\n\nCreate one storage account in the Azure portal. After the account exists, create a private `microbundles` container and grant the development Microsoft Entra identity **Storage Blob Data Contributor** on the storage account.\n\nThe repository uses `DefaultAzureCredential`, so no storage account key belongs in source control.\n\n## Storage account URI\n\nThe application needs only the storage account endpoint:\n\n~~~text\nhttps://<storage-account-name>.blob.core.windows.net\n~~~\n\nFor local development, pass it through `MICROBUNDLE_STORAGE_ACCOUNT_URI`.\n\n## Repository operations\n\n~~~csharp\nvar repository = new AzureMicroBundleRepository(\n    new AzureMicroBundleRepositoryOptions\n    {\n        StorageAccountUri = new Uri(storageAccountUri)\n    });\n\nawait repository.InitializeAsync();\nawait repository.PutAsync(artifact);\nvar retrieved = await repository.GetAsync(address);\n~~~\n\nA missing blob returns `null`. A blob whose bytes do not match the requested SHA-256 address cannot become a `MicroBundleArtifact`.\n\n## Cost boundary\n\nKeep the first repository deliberately small: one LRS/Hot storage account, one private container, no extra Azure services.\n\n## Architecture rule\n\n**Blob Storage is the substrate. The repository is the delivery boundary. FSM_COS is the composition boundary.**\n\nDo not add a database merely to make blob artifacts queryable. If discovery later requires indexing, design that as a purpose-built artifact/catalog structure rather than silently turning the repository into a CRUD database.\n
